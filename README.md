# Error Free Text

REST-сервис для автоматической проверки и исправления текста с использованием Yandex Speller.

## Стек технологий

- Java 25
- Spring Boot 3.5
- Gradle
- PostgreSQL 17
- Spring Data JPA
- Flyway
- Docker
- Docker Compose
- Yandex Speller API
- JUnit 5
- Mockito

## Возможности

- создание задачи на проверку текста;
- асинхронная обработка задач;
- автоматическая проверка текста через Yandex Speller;
- поддержка русского и английского языков;
- обработка текста длиной более 10 000 символов;
- автоматическое разбиение длинного текста на части;
- игнорирование цифр и URL при проверке;
- хранение задач и результатов в PostgreSQL;
- валидация входных данных;
- обработка ошибок REST API;
- unit-тесты.

## Запуск проекта

Для запуска необходим установленный Docker.

Клонировать репозиторий:

```bash
git clone https://github.com/uglezhuy/error-free-text.git
cd error-free-text
```

Запустить приложение:

```bash
docker compose up --build
```

После запуска приложение будет доступно по адресу:

```text
http://localhost:8080
```

Для остановки приложения:

```bash
docker compose down
```

## API

### Создание задачи

```http
POST /tasks
```

Пример запроса:

```bash
curl -X POST http://localhost:8080/tasks \
  -H "Content-Type: application/json" \
  -d '{"text":"Превед медвед","language":"RU"}'
```

Пример ответа:

```json
{
  "id": "3f754220-a3d2-4465-a8be-01889e874087",
  "status": "NEW",
  "correctedText": null,
  "errorMessage": null
}
```

После создания задача автоматически передается на обработку scheduler'ом.

### Получение задачи

```http
GET /tasks/{id}
```

Пример:

```bash
curl http://localhost:8080/tasks/3f754220-a3d2-4465-a8be-01889e874087
```

При успешно завершенной обработке:

```json
{
  "id": "3f754220-a3d2-4465-a8be-01889e874087",
  "status": "DONE",
  "correctedText": "Превед медвед",
  "errorMessage": null
}
```

## Статусы задач

| Статус       | Описание                              |
| ------------ | ------------------------------------- |
| `NEW`        | Задача создана и ожидает обработки    |
| `PROCESSING` | Задача находится в процессе обработки |
| `DONE`       | Обработка успешно завершена           |
| `ERROR`      | Во время обработки произошла ошибка   |

## Валидация

Поддерживаются следующие языки:

```text
RU
EN
```

Текст должен:

- содержать минимум 3 символа;
- содержать хотя бы одну букву;
- не состоять только из цифр и специальных символов.

При некорректных входных данных API возвращает HTTP `400`.

Если задача с указанным UUID не существует, API возвращает HTTP `404`.

Пример ошибки:

```json
{
  "errorMessage": "Task with id: 44bd78dc-d08c-41c6-b87d-fb820460 not found",
  "errorCode": 40401,
  "timestamp": "2026-10-05T12:00:00",
  "path": "/tasks/44bd78dc-d08c-41c6-b87d-fb820460"
}
```

## Yandex Speller

Для проверки текста используется Yandex Speller API:

```text
https://speller.yandex.net/services/spellservice.json/checkTexts
```

Yandex Speller позволяет отправлять не более 10 000 символов в одном тексте.

Если исходный текст превышает это ограничение, приложение автоматически разбивает его на части и отправляет каждую часть отдельно.

При обработке используются следующие параметры:

- `IGNORE_DIGITS` — включается, если текст содержит цифры;
- `IGNORE_URLS` — включается, если текст содержит URL;
- `FIND_REPEAT_WORDS` — не используется;
- `IGNORE_CAPITALIZATION` — не используется.

После получения ответа от Yandex Speller приложение применяет найденные исправления к исходному тексту и сохраняет результат в базе данных.

Если Yandex Speller возвращает ошибку, задача переводится в статус `ERROR`, а описание ошибки сохраняется в базе данных.

## Асинхронная обработка

После создания задача получает статус `NEW`.

Scheduler запускается периодически и ищет новые задачи:

```text
NEW → PROCESSING → DONE
```

При возникновении ошибки:

```text
NEW → PROCESSING → ERROR
```

Проверка новых задач выполняется автоматически без необходимости дополнительного запроса от клиента.

## База данных

PostgreSQL запускается автоматически через Docker Compose.

Для управления схемой базы данных используется Flyway.

Основная таблица:

```text
tasks
```

Таблица содержит:

- идентификатор задачи;
- исходный текст;
- язык;
- исправленный текст;
- статус;
- сообщение об ошибке;
- дату создания;
- дату обновления.

Данные PostgreSQL сохраняются в Docker volume:

```text
postgres-data
```

Поэтому данные не удаляются при обычном перезапуске контейнеров.

## Docker

Проект состоит из двух основных контейнеров:

```text
error-free-text-app
        │
        ▼
Spring Boot
        │
        ▼
PostgreSQL
error-free-text-db
```

Docker Compose автоматически:

1. запускает PostgreSQL;
2. ожидает готовности базы данных;
3. собирает Spring Boot приложение;
4. запускает приложение;
5. приложение подключается к PostgreSQL;
6. Flyway выполняет миграции;
7. запускается REST API и scheduler.
